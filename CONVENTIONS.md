# Contribution conventions

## Commits and pull requests

Keep each commit and pull request focused on one logical change. Avoid unrelated cleanup so changes remain easy to review and revert.

Keep PR descriptions concise. Explain the problem, the resulting behavior, and how the change was validated. For small changes, one or two sentences plus validation are enough. Report the checks actually run and their results; if checks were not run, state why.

Include risks, migration steps, and issue links when relevant. Keep the description aligned with the final diff and omit empty boilerplate sections.

Reference: [GitHub: Helping others review your changes](https://docs.github.com/en/pull-requests/concepts/helping-others-review-your-changes).
